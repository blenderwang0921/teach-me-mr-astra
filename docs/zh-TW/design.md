# 本機 C++ 教學實驗室 — 已實作的 v1 設計

[English](../design.md) | 繁體中文

原始繁體中文交接文件為 [design.md](../../design.md)。本文件的英文版是前三個交付階段的主要實作設計文件。設計意圖、已驗證的行為與未來的學習成果會分開描述。

## 目的與界線

學習者在本機練習 C++ 實作、除錯、演算法、並行處理與系統設計判斷。教師透過簡短訪談、短篇校準任務與實作證據，選出一個適合的下一項挑戰。目標是以更少協助將能力轉移到新情境，而非追求測驗分數或排名。

本系統沒有網頁介面、預設課程、雲端執行器、額外 API 金鑰、自動模型路由或精熟度分類器。練習只會在訪談後產生。實作與除錯範本是編寫教材的骨架；小型計數器測試夾具用於框架測試，絕不指派為課程。

儲存庫預設為私人，追蹤學習歷程、產生的任務、教師資產與持久保存的證據。公開發布時應匯出不含私人紀錄與答案的框架。教師目錄用來降低意外洩漏的機會，不是存取控制機制。

## 職責

| 元件 | 負責事項 |
| --- | --- |
| 教師 | 訪談、選擇目標、語意審查、診斷、提示、解讀與下一步行動。 |
| 教學文件 | 各階段政策、語言、協助程度與編輯界線。 |
| 學習者狀態 | 目標、偏好、分開保存的自述與觀察、目前階段及持久參照。 |
| 練習契約 | 情境、API、需求、測試對應、可編輯與提供的路徑、修訂版及限制。 |
| 固定工具 | 驗證、程序控制、可重現的建置與測試、報告及狀態交易。 |

CLI 中的啟發式規則不會取代教師決策。腳本絕不透過模型產生缺少的練習。正確的參考實作是必要條件，但並不足夠：教師負責語意審查，工具則驗證與目標相關的特定缺陷及學習者骨架的行為。

除文件翻譯外，所有正式文件、產生的資產、程式碼註解與可重用摘要均使用英文。`docs/` 中的英文文件是主要維護版本；翻譯放在 `docs/<language>/` 下，使用相同檔名（目前支援 `zh-TW`）。新增、修改、重新命名或刪除文件時，必須在同一次變更同步更新所有支援語言及受影響的連結；未來新增的語言也適用。對話語言獨立設定，初始為 `zh-TW`。學習者原始回答與上游聲明保留原本語言。

## 建置與執行

CLI 使用 Python 與 JSON Schema。CMake/Ninja 從 `src/**/*.cpp`、`tests/**/*.cpp` 與 `include/` 建立一個練習測試目標。v1 不允許練習提供任意替代建置介接器。預設使用 C++20，C++23 則依目標選用。Catch2 固定使用 v3.8.1 的不可變提交，快取存放於受追蹤原始碼之外。

可用組態包含 debug、release、ASan+UBSan，以及獨立的 TSan。每個要求的組態都必須編譯並執行真正的能力探測。無法支援的必要檢查視為失敗，不算成功略過。每次執行都保留確切的編譯器與標準函式庫資訊。平台專屬任務須明確宣告 Linux/macOS；Windows 支援延後處理。

CTest 探索具名的公開檢查，拒絕零測試或缺漏測試、套用有上限的逾時，並輸出 JUnit 證據。每個宣告的種子值都會執行。建置平行度與程序逾時均有上限；終止程序群組可避免遺留子程序。測試不是隔離沙箱，v1 也不強制執行記憶體配額。

## 契約與證據

結構描述涵蓋個人資料、工作階段、練習、驗證、證據、審查、教材、目錄、就緒標記、狀態更新與執行報告。結構化資料使用結構描述版本 1。未定義的公開欄位會被拒絕；學習者原始文字與偏好則在適當處保留彈性。

個人資料保存目標、時間、平台、語言、偏好與自述經驗。證據觀察紀錄只能附加，包含技能、修訂版與提示程度，並參照持久保存的程式碼快照、報告或學習者說明。教師的信心程度是暫時判斷，未經統計校準。更正時會附加一筆參照前一筆的新觀察。

報告區分實際執行的原始碼雜湊與學習者原始目錄樹的雜湊，讓額外教師測試覆蓋進來時仍能保留來源脈絡。完整日誌與建置產物可以丟棄；精簡結果、有長度上限的失敗診斷、確切種子值與執行原始碼快照仍持續追蹤。缺少佐證會回報為完整性問題。無法取得可信測量值時，用量欄位維持 null。

狀態變更需要一個由作業系統持有的寫入鎖，以及預期的工作階段版本。驗證後，重做日誌會記錄完整替換內容，再以原子方式替換檔案。重新啟動時，在同一把鎖下重播日誌。證據檔案雖然以原子方式替換，其歷史在邏輯上仍只附加。版本衝突會失敗，不會默默覆寫另一個工作階段。

## 發布與修訂規則

先編寫情境與可觀察需求，再撰寫參考實作、測試、刻意植入缺陷的變異版本與骨架。參考實作、骨架與變異版本目錄只包含可編輯路徑，並覆蓋到提供檔案的隔離副本上。範本刻意設計成無法發布，直到佔位內容與語意審查旗標被替換。

準備流程會驗證結構描述與路徑所有權、執行參考實作的 debug 與必要 sanitizer 組態、檢查骨架宣告的功能失敗（或明確宣告的除錯編譯失敗），並要求每個變異版本在指定測試中失敗。單純編譯失敗，無法證明功能性變異缺陷已被偵測。公開驗收測試與額外教師測試也會對學習者版本執行。

發布成功時會保存就緒標記，綁定練習識別碼、修訂版、契約雜湊與持久驗證報告。契約對提供檔案、規格、教師資產、結構描述及執行與建置工具計算雜湊；一般可編輯檔案的變更不會使其失效。已發布契約若有變更，必須遞增修訂版並明確重新驗證。重複準備不能覆寫學習者的成果。

學習者檢查使用不可變快照，並將執行期間的程式碼或契約變更記為完整性失敗。單一組態檢查僅供診斷。只有涵蓋全部必要組態的預設檢查，才會更新工作階段中符合資格的報告。

## 教學生命週期

正常順序為 onboarding → planning → preparing → practicing → reviewing → planning。暫停的工作階段保留恢復階段與原因。準備失敗會阻止指派；學習者測試失敗則維持 practicing。已記錄的練習缺陷可讓任務回到 preparing，建立新的修訂版，而不歸咎於學習者。

教師先讀取狀態，並只讀取相關階段指引、目前契約、近期觀察與報告。不會重新載入整段對話，也不會在學習者工作期間持續輪詢。提示範圍從預測問題、反例、概念、虛擬碼，到明確要求後才提供的完整解答。所有協助均如實記錄。

測試通過後，學習者說明一項決策，或預測需求改變後的結果。完成練習需要該說明、審查、目前成功的必要組態證據，以及未變動的學習者檔案。這不代表已精熟。後續任務應在不同情境及更少協助下檢驗能力轉移。

系統設計練習會圍繞一個可執行元件，加入設計筆記及可重現的負載與失敗實驗。容量估算與取捨需要教師審查。單元測試無法認證整體架構。

## 驗證與延後工作

行為測試聚焦於復原、版本衝突、只能附加的證據、路徑所有權、契約失效、失敗分類與發布門檻。真正的 C++ 整合測試夾具涵蓋初始化、提示、模擬學習者修正、說明與審查、刪除完整日誌，以及在新程序中復原。這些檢查驗證的是工具，而非人的學習成果。

GitHub Actions 設定了 Linux Clang/GCC 驗證，並檢查已宣告完成的學習者成果；尚未完成的任務不會使框架 CI 失敗。遠端結果必須與本機檢查分開回報。

教材清單與目錄支援後續候選教材篩選，但上游執行與重設介接器延後處理。未來教材必須固定來源與提交、保留授權、記錄確切環境，並展示基準可重現性，才能標記為就緒。第一版不宣稱任何上游專案已完成驗證。

Token 計量、十次工作階段的成本檢視、選用工作程序、大型教材庫、排程與 Windows 支援，均留待後續處理。教學規則未內嵌任何訂閱配額或模型名稱。學習成功仍需要在新情境中實際獨立完成實作與說明。
