# 環境與可重現性

[English](../environment.md) | 繁體中文

## 基準環境

- Python 3.11+；相依套件與間接相依套件固定於 `uv.lock`。`uv sync --frozen` 會將 Ninja 1.13.0 與 jsonschema 4.25.1 安裝至 `.venv`。
- CMake 3.25+，使用預設組態結構描述版本 6；建置產生器為 Ninja；CTest 隨 CMake 提供。
- 預設 C++20，依規格選用 C++23。主要使用 Clang；Linux CI 也會明確選用 GCC。
- Catch2 v3.8.1，固定提交為 `56809e5282f104c5c8b570e7c2996cdc352d94f1`。固定版本的 Git 工作副本保留上游授權，採快取方式保存，不將其原始碼納入框架。
- 不需要模組、套件層級的效能測試函式庫、容器或模型 API 憑證。

每次執行都會記錄編譯器路徑與版本、標準函式庫識別碼、Python、平台、預設組態、指令、種子值、耗時、結果，以及原始碼與契約雜湊。主機架構與核心差異仍有影響；記錄版本不代表能逐位元重現結果。

## 選擇工具

啟用 `.venv`，再視需要將 `CXX` 設為編譯器執行檔。它必須是單一執行檔路徑或名稱，不能是含有旗標的 shell 指令。即使未啟用環境，實驗室也能找到 Python 直譯器旁的 Ninja。

```sh
export CXX=clang++
python tools/lab.py doctor --json
```

本機使用 Apple Silicon 上的 macOS 14.5、Python 3.14.3、CMake 4.3.1，以及搭配 libc++ 220102 的 Homebrew LLVM 22.1.2。LLVM 的 debug、ASan+UBSan 與 TSan 能力探測均通過。預設 Apple Clang 16.0.0 找不到標準標頭檔；只依版本選擇編譯器會漏掉這個問題。請明確使用既有 LLVM：

```sh
export CXX=/opt/homebrew/opt/llvm/bin/clang++
```

不要為了修復此專案而全域替換系統編譯器。手動使用 CMake 時，將主機專屬預設組態放在已忽略的 `CMakeUserPresets.json`。執行實驗室 CLI 時，透過 `CXX` 選擇編譯器；其內建組態名稱固定不變。

## 組態與限制

`debug` 與 `release` 的建置類型不同。`asan` 啟用位址與未定義行為檢查；`tsan` 另外啟用執行緒檢查。Sanitizer 會對練習原始碼與測試加入檢測。Catch2 本身使用正常建置設定。必要組態必須先編譯並執行能力探測，才能測試；無法使用的必要組態會明確失敗。

規格限制建置平行度、每項測試與每個指令。指令在程序群組中執行，逾時會終止整個群組。這是執行管理措施，不是用於不可信 C++ 或上游儲存庫的沙箱。不要僅因為有逾時限制，就執行不可信的練習。目前資源限制不包含硬性記憶體配額。

Linux CI 以 Ubuntu 24.04、Clang 18/GCC 14 及 Python 3.11/3.14 為目標。整合測試夾具會執行 ASan+UBSan。雖然會探測 TSan 能力，但實際並行正確性需要專門的並行練習與測試；系統不會預先指派這類練習。

## 疑難排解

- 缺少工具：使用平台的套件管理器安裝，再執行 `doctor`。
- 相依套件網路失敗：保留報告，待連線恢復後重試一次。不使用未驗證的替代相依套件。
- 編譯器成功但 sanitizer 無法執行：檢查能力探測細節與平台。不要默默移除已指派任務的必要 sanitizer。
- 契約變更：遞增練習修訂版、記錄原因，再執行 `prepare`。僅有學習者編輯不需要變更修訂版。
- 原始碼或測試探索失敗，或零測試：修復練習或框架，而非修改學習者能力紀錄。

## 相依套件快取行為

Catch2 固定版本指向的是附註標籤物件。與 HEAD 比較前，先用 `^{commit}` 解析。只有固定物件不存在時才擷取；每次使用都驗證工作目錄。有效快取必須能在無法連線 GitHub 時運作。在 macOS 上，實驗室會自動選擇已安裝的 Homebrew LLVM，除非 CXX 覆寫此選擇。
